문제

stock_daily_prices 에서 종목별로 '3일 이상 연속 상승한 구간' 을 모두 찾으세요. stock_code streak_start_date 그 구간의 첫 상승일 streak_end_date 그 구간의 마지막 상승일 streak_days 그 구간의 연속 상승 일수 · 상승일 = 전 거래일 종가보다 당일 종가가 '더 높은' 날 (같으면 상승이 아닙니다). · 전 거래일은 하루 전이 아니라 그 종목의 데이터상 바로 앞 행입니다. · streak_days 는 상승일의 개수입니다. 상승이 시작되기 전 날은 세지 않습니다. · 구간이 3일 미만이면 출력하지 않습니다. · stock_code 오름차순, 같으면 streak_start_date 오름차순으로 정렬하세요.
정렬 stock_code ASC, streak_start_date ASC

이렇게 푼다

  1. 전체 줄에 먼저 번호를 매기고, 어제 종가도 같이 끌어온다.
  2. 오른 날만 남긴다 (오늘 > 어제).
  3. 남은 것에 번호를 새로 매기고, (전체 줄번호 − 새 번호).
  4. 그 값으로 묶어서 시작일·끝일·개수, 3 이상만.

이것만 피하면 된다

  • 번호는 거르기 전에 매겨야 한다. 거른 다음에 매기면 빠진 자리가 메워져서 끊긴 구간이 붙어 버린다. 이게 핵심이고 여기서 대부분 틀린다.
  • 날짜 차이로 묶으면 틀린다. 금요일과 월요일은 날짜로는 3일 차이지만 거래일로는 바로 연속이다. 주말에 데이터가 없으니까. 줄 번호를 써야 한다.
  • 같은 가격은 상승이 아니다. > 지 >= 가 아니다.

자세히

묻는 것 · LAG 로 상승일을 가리고, 그 위에 gaps and islands 를 한 번 더 얹는다. 두 패턴을 포개는 문제. 이게 풀리면 시계열 문제는 거의 다 풀린다.

풀이 순서

  1. 먼저 모든 행에 행 번호를 매긴다: ROW_NUMBER() OVER (PARTITION BY stock_code ORDER BY trade_date) AS rn. 이게 '몇 번째 거래일인가' 다. 날짜가 아니라 이 번호가 기준이 된다.
  2. 같은 단에서 LAG(close_price) OVER (PARTITION BY stock_code ORDER BY trade_date) 로 전 거래일 종가를 끌어온다.
  3. WHERE prev IS NOT NULL AND close_price > prev 로 상승일만 남긴다.
  4. 남은 상승일에 새로 행 번호를 매기고 rn − 새 행번호 → 연속 상승 구간마다 같은 값.
  5. 그 값으로 묶어 MIN/MAX/COUNT, HAVING COUNT(*) >= 3.

정답 (MySQL)

WITH p AS (
  SELECT stock_code, trade_date, close_price,
         ROW_NUMBER() OVER (PARTITION BY stock_code ORDER BY trade_date) AS rn,
         LAG(close_price) OVER (PARTITION BY stock_code ORDER BY trade_date) AS prev
  FROM stock_daily_prices
),
u AS (
  SELECT stock_code, trade_date,
         rn - ROW_NUMBER() OVER (PARTITION BY stock_code ORDER BY trade_date) AS grp
  FROM p
  WHERE prev IS NOT NULL AND close_price > prev
)
SELECT stock_code,
       MIN(trade_date) AS streak_start_date,
       MAX(trade_date) AS streak_end_date,
       COUNT(*) AS streak_days
FROM u
GROUP BY stock_code, grp
HAVING COUNT(*) >= 3
ORDER BY stock_code, streak_start_date;

함정

  • 날짜 차이로 구간을 묶으면 틀린다. 주말이 비어 있어서 금요일과 월요일은 날짜로는 3일 차이지만 거래일로는 연속이다. DATEDIFF 대신 행 번호를 일련번호로 써야 한다. 「끊김복귀」·「동점」 데이터셋이 이걸 잡는다.
  • rn 은 상승일만 걸러낸 뒤에 매기면 안 된다. 전체 행에 먼저 매겨 둬야 '거래일 순서' 가 보존된다. 걸러낸 뒤 매기면 하락일이 사라진 자리가 메워져 끊긴 구간이 붙어 버린다.
  • > 와 >= 는 다른 문제다. 전일과 같은 가격은 상승이 아니다. 「경계값」 데이터셋에 같은 가격이 들어 있다.
  • prev IS NOT NULL 을 빼면 첫 행이 섞인다. 각 종목의 첫 거래일은 전일이 없어서 LAG 가 NULL 이다. close_price > NULL 은 NULL(거짓 취급)이라 대부분 자동으로 빠지지만, 명시하는 편이 안전하고 읽기도 낫다.
  • streak_days 는 상승일의 개수다. 상승이 시작되기 전 날(기준이 된 날)은 세지 않는다. 세어야 하는 문제면 COUNT(*) + 1 이고 시작일도 하루 앞이 된다. 문제를 다시 읽어라 — 출제자가 어느 쪽을 묻는지가 갈린다.
  • PARTITION BY stock_code 를 LAG 와 ROW_NUMBER 양쪽에 다 써라. 하나라도 빠지면 종목이 넘어가는 지점에서 앞 종목의 마지막 가격과 비교해 버린다.

이렇게 변형된다

“N일 연속 하락”이면 부등호만 뒤집는다. “최장 구간 하나만”이면 마지막에 ROW_NUMBER() OVER (PARTITION BY stock_code ORDER BY COUNT(*) DESC) 로 1등만. “연속 상승률”이면 구간 양 끝 종가가 필요하므로 FIRST_VALUE/LAST_VALUE 를 쓰거나 시작일 하루 전 종가를 따로 끌어온다.
