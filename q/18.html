유저별 최장 연속 거래일수

난이도 어려움 · 권장 18분 · 출력 컬럼 user_id, max_streak_days
이 문제 직접 풀어보기 →

문제

stock_orders 에서 유저별 '가장 길게 연속으로 거래한 일수' 를 구하고, 그 값이 3 이상인 유저만 뽑으세요. user_id max_streak_days 최장 연속 거래일수 · status = 'COMPLETED' 인 주문만 셉니다. · 하루에 여러 번 거래했어도 그 날은 1일입니다. · 그 날 주문이 전부 CANCELLED 면 거래하지 않은 날입니다 (연속이 끊깁니다). · 날짜가 하루씩 이어진 구간만 연속입니다. 주말·공휴일은 따지지 않습니다. · max_streak_days 내림차순, 같으면 user_id 오름차순으로 정렬하세요.
정렬 max_streak_days DESC, user_id ASC

쉽게 설명하면

Q8 의 출석 도장 트릭과 똑같다. 단위가 '달' 에서 '날' 로 바뀐 것뿐.

거래한 날날 번호줄 번호차이
3월 2일60159
3월 3일61259
3월 4일62359
3월 8일66462

차이 59 가 세 개 → 3연속. 그 다음은 끊긴 것.

이렇게 푼다

  1. 성공한 주문만 남기고, 하루는 1번으로 중복을 지운다. 이 한 줄에 문제 조건 두 개가 다 들어 있다.
  2. 날짜를 숫자로 바꾼다.
  3. 날 숫자 − 줄 번호 → 묶어서 개수 → 사람별 최대값 → 3 이상만.

이것만 피하면 된다

  • 취소된 주문을 빼라. 그 날 주문이 전부 취소면 거래 안 한 날이고, 연속이 거기서 끊겨야 한다.
  • 하루 여러 건을 1건으로 지워라. 하루에 3건 거래했으면 줄 번호가 3칸 가는데 날짜는 그대로여서 연속일수가 부풀어 오른다.
  • 동점이 아주 많은 문제다. 최장일수 DESC, user_id ASC 둘 다 써라.

자세히

묻는 것 · gaps and islands. 알면 2분, 모르면 못 푼다. 반드시 외워 둘 패턴.

풀이 순서

  1. 먼저 조건을 걸고 하루 단위로 중복을 지운다: SELECT DISTINCT user_id, order_date ... WHERE status='COMPLETED'. 이 한 줄에 문제의 조건 두 개가 다 들어 있다.
  2. 날짜를 일련번호로 바꾼다: DATEDIFF(order_date, '기준일').
  3. 일련번호 − ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY order_date) → 연속 구간마다 같은 값이 나온다.
  4. 그 값으로 묶어 COUNT(*) → 구간 길이. 유저별 MAX() → 최장 길이. HAVING 으로 3 이상만.

정답 (MySQL)

WITH d AS (
  SELECT DISTINCT user_id, order_date
  FROM stock_orders
  WHERE status = 'COMPLETED'
),
g AS (
  SELECT user_id, order_date,
         DATEDIFF(order_date, '2026-01-01')
         - ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY order_date) AS grp
  FROM d
),
runs AS (
  SELECT user_id, grp, COUNT(*) AS run_len
  FROM g GROUP BY user_id, grp
)
SELECT user_id, MAX(run_len) AS max_streak_days
FROM runs
GROUP BY user_id
HAVING MAX(run_len) >= 3
ORDER BY max_streak_days DESC, user_id ASC;

함정

  • 왜 되는가. 연속이면 날짜 일련번호와 행 번호가 같은 보폭으로 늘어나 차이가 고정된다. 끊기면 차이가 점프한다.
    3/2,3/3,3/4 → 60,61,62 − 1,2,3 = 59,59,59 (한 구간)
    3/2, 3/6 → 60,64 − 1,2 = 59,62 (다른 구간)
  • DISTINCT 를 빼면 연속일수가 부풀어 오른다. 하루에 3건 거래했으면 ROW_NUMBER 가 세 칸 가는데 날짜는 그대로라 차이가 틀어진다.
  • status 필터를 빼면 끊겨야 할 구간이 이어진다. 그 날 주문이 전부 CANCELLED 면 거래하지 않은 날이다. 「끊김복귀」 데이터셋이 이걸 잡는다.
  • HAVING 에 MAX(run_len) 을 그대로 쓴다. WHERE run_len >= 3 으로 미리 걸러도 같은 답이 나오지만, 그러면 '최장 구간이 3 미만인 유저' 와 '3 이상 구간만 남긴 유저' 의 MAX 가 달라질 수 있는 변형 문제에서 틀린다.
  • 정렬 두 개를 다 쓴다. 동점이 많은 문제다. max_streak_days DESC 만 쓰면 같은 값들 사이 순서가 실행마다 바뀐다.

이렇게 변형된다

“연속 출석일수”, “N일 연속 접속”, “연속 결제 개월수” 전부 같은 패턴이다. 월 단위면 일련번호를 TIMESTAMPDIFF(MONTH, 기준월, 그달) 로 바꾼다. “현재 진행 중인 연속일수”면 마지막 구간만 (MAX(order_date) = 오늘 인 구간) 남긴다.
