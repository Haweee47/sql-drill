가입 코호트별 월간 리텐션

난이도 어려움 · 권장 18분 · 출력 컬럼 cohort_month, cohort_size, m1_retention, m2_retention, m3_retention
이 문제 직접 풀어보기 →

문제

가입 월을 코호트로 삼아 M+1, M+2, M+3 리텐션(%)을 구하세요. · 잔존 기준: 해당 월에 app_open 이벤트가 1건 이상 있으면 잔존으로 봅니다. · 리텐션 = 그 달에 활동한 코호트 인원 / 코호트 전체 인원 × 100 · 소수점 첫째 자리까지 반올림합니다. · 코호트 오름차순으로 정렬하세요.
정렬 cohort_month ASC

쉽게 설명하면

3월에 입학한 애들이 1달 뒤·2달 뒤에 몇 명 남았나. 입학한 달마다 따로 추적한다. 반이 다르면 섞지 않는다.

가입 월0개월1개월2개월
1월 (100명)100%42%28%
2월 (120명)100%38%25%

가로가 '가입 후 몇 달째', 세로가 '언제 가입한 묶음'. 분모는 그 줄의 전체 인원이고 끝까지 안 바뀐다.

이렇게 푼다

  1. 사람마다 가입한 달을 붙인다. 이게 그 사람이 속한 '묶음' 이다.
  2. 접속 기록마다 가입 후 몇 달째인가를 계산한다 (접속한 달 − 가입한 달).
  3. 가입한 달 × 경과 개월로 묶어서 사람 수를 센다.
  4. 그 수를 그 묶음의 전체 인원으로 나눈다.

이것만 피하면 된다

  • 분모는 접속 기록에서 세면 안 된다. 가입한 사람 명단에서 세야 한다. 접속 기록에서 세면 '접속한 사람 중 접속한 사람' 이 되어 항상 100% 가 나온다.
  • 사람 수는 중복을 지우고 센다. 한 달에 열 번 접속한 사람은 한 명이다.

자세히

묻는 것 · 코호트 분석의 뼈대. 분모 고정 + 경과 개월.

풀이 순서

  1. 코호트 = 가입 월. 유저마다 하나.
  2. 활동 = app_open 이 있는 월. 유저×월 중복 제거.
  3. TIMESTAMPDIFF(MONTH, 코호트, 활동월) 로 경과 개월 M+1, M+2…
  4. 분모는 코호트 전체 인원. 활동 안 한 사람도 포함.

정답 (MySQL)

WITH base AS (
  SELECT user_id, DATE_FORMAT(signup_date, '%Y-%m-01') AS cohort FROM users
),
act AS (
  SELECT DISTINCT user_id, DATE_FORMAT(event_date, '%Y-%m-01') AS m
  FROM events WHERE event_name = 'app_open'
)
SELECT DATE_FORMAT(b.cohort, '%Y-%m') AS cohort_month,
       COUNT(DISTINCT b.user_id) AS cohort_size,
       ROUND(100.0 * COUNT(DISTINCT CASE WHEN TIMESTAMPDIFF(MONTH, b.cohort, a.m)=1
             THEN b.user_id END) / COUNT(DISTINCT b.user_id), 1) AS m1_retention,
       ROUND(100.0 * COUNT(DISTINCT CASE WHEN TIMESTAMPDIFF(MONTH, b.cohort, a.m)=2
             THEN b.user_id END) / COUNT(DISTINCT b.user_id), 1) AS m2_retention,
       ROUND(100.0 * COUNT(DISTINCT CASE WHEN TIMESTAMPDIFF(MONTH, b.cohort, a.m)=3
             THEN b.user_id END) / COUNT(DISTINCT b.user_id), 1) AS m3_retention
FROM base b
LEFT JOIN act a ON a.user_id = b.user_id
GROUP BY cohort_month
ORDER BY cohort_month;

함정

  • INNER JOIN 금지. 한 번도 활동 안 한 유저가 분모에서 빠지면 리텐션이 과대평가된다.
  • 분모를 COUNT(*) 로 쓰면 안 된다. 조인으로 행이 불어나 있다. COUNT(DISTINCT user_id).
  • 활동 테이블에서 유저×월 중복 제거를 먼저 해야 한다. 안 하면 한 유저가 여러 번 세어질 수 있다 — DISTINCT 를 써서 막는다.
  • 아직 기간이 안 지난 코호트는 0 이 나온다. 정상이다.

이렇게 변형된다

주 단위면 TIMESTAMPDIFF(WEEK, ...). “결제 리텐션”이면 활동 테이블을 payments 로 바꾼다.
